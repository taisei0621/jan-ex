# ソフトウェア開発演習 制作計画レポート

## 1. プロダクト基本情報
- **プロダクト名称**：雀EX（Jan-EX / 異次元麻雀プラットフォーム）
- **本番公開環境URL**：`https://<your-vercel-app>.vercel.app`（※Vercel連携後に記載）
- **ソースコードリポジトリURL**：`https://github.com/<your-account>/jan-ex`（※GitHubプッシュ後に記載）

## 2. 解決すべき課題と対象利用者
- **対象とする単一の利用者**：既存の麻雀アプリ（雀魂・天鳳・MJ）の通常ルールに飽きた開発者自身、およびYouTube等で特殊ルール麻雀を見て興味を持った麻雀好きの友人。
- **切実な不便**：YouTubeや身内で大人気の「少牌マイティ」「鷲巣麻雀（透明ガラス牌）」「東天紅（完全加算サンマ）」「マーチャオAルール（金牌・白ポッチ）」は、既存の大手麻雀アプリに一切実装されておらず、1人でルールを体験したり、高打点スコアや推理パズルを友人と競ったりする手段がない。
- **現在の代替手段とその限界**：実際の牌やガラス牌を用意して4人集める必要がある。少牌マイティの「何待ちか（10面待ち等）」を人間の頭だけで瞬時に判定するのは困難。

## 3. 中核的価値
- **提供する決定的な価値**：通常麻雀の前提を覆す4種の特殊ルール（ワイルドカード、75%透明ガラス牌、完全加算式サンマ、白ポッチ祝儀）をブラウザ上で即座に体験でき、全国スコアランキング（Supabase）を通じて競い合える点。

## 4. 技術スタックの選定理由と自習計画
- **フロントエンド**：Next.js (App Router) + TypeScript + Tailwind CSS（型安全性によりエージェント生成コードの破綻を防ぎ、URL共有のみで即時体験可能）
- **バックエンドおよびデータベース**：Supabase (PostgreSQL)（クレジットカード登録不要の無償枠で全国ランキング・パズル共有を永続化可能）
- **ホスティング環境**：GitHub + Vercel（`main` ブランチへのプッシュで自動ビルド＆本番配備）
- **自動テスト・ハーネス**：Vitest（特殊ルールの和了判定・点数計算の回帰バグを機械的に防止）

## 5. 8週間の垂直スライス開発計画
- **第1週**：少牌マイティ（12枚＋★マイティ）の和了判定エンジン＋UI＋Supabase全国ランキング保存＋Vercel初公開（全層貫通）。
- **第2週**：実牌画像（`pai-images`）の統合と、鷲巣麻雀（透明ガラス牌）の相手当たり牌推理パズル実装。
- **第3週**：東天紅（2m〜8m抜き・北自動ガリ抜き・完全加算式）のスコアアタック実装＋ランキング対応。
- **第4週**：友人・ゼミ生による実機テストとフィードバック収集、UI/操作性（待ち牌表示・1クリック打牌）の改善ピボット。
- **第5週**：マーチャオAルール（金牌・白ポッチ）の統合と、全エンジンに対するVitest自動テスト網羅。
- **第6週**：自作「鷲巣麻雀パズル」をURL1本で友人に共有・挑戦できる機能（Supabase永続化）。
- **第7週**：モバイルレスポンシブ最適化、セキュリティ点検（RLSポリシー・環境変数分離）、パフォーマンス改善。
- **第8週**：実運用データ・全国ランキングを用いた成果実演と総括。

## 6. ハーネス設計と品質管理方針
- **自動テストの導入計画**：Vitest を導入し、`src/engine/` 配下の和了判定・待ち牌抽出・点数計算ロジックに対する単体テストを毎回実行する。
- **エージェント規範定義の導入計画**：`AGENTS.md` に型検査（`npx tsc --noEmit`）・テスト（`npm test`）・UI/ロジック分離・環境変数保護ルールを明文化する。
