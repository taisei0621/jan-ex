# ソフトウェア開発演習 制作計画レポート

## 1. プロダクト基本情報
- **プロダクト名称**：雀EX（Jan-EX）— 少牌マイティ特化型 異次元麻雀プラットフォーム
- **本番公開環境URL**：https://jan-ex-f8b5.vercel.app/
- **ソースコードリポジトリURL**：https://github.com/taisei0621/jan-ex.git

## 2. 解決すべき課題と対象利用者
- **対象とする単一の利用者**：通常の麻雀アプリ（雀魂・天鳳・MJ）の進行速度や通常ルールにマンネリを感じている開発者自身、およびYouTube等で「少牌マイティ」を知って遊んでみたいと感じている麻雀好きの友人。
- **切実な不便**：YouTubeや一部雀荘で大人気の特殊ルール「少牌マイティ（手牌12枚＋常に何でも化ける万能★マイティ牌1枚）」は、既存の大手オンライン麻雀アプリに一切実装されていない。また、実際の麻雀牌で遊ぼうとしても「★マイティがあるせいで今何待ち（10面待ち等）なのか」「最高打点の役が何か」を人間の頭だけで瞬時に判定するのが非常に困難である。
- **現在の代替手段とその限界**：実際の牌を4人分集めて手計算するしかなく、1人で手軽に練習したり、友人と同じ条件でハイスコアを競ったりする手段が存在しない。

## 3. 中核的価値
- **提供する決定的な価値**：手牌12枚＋万能★ワイルドカードの和了・多面待ち・最高打点をリアルタイム自動判定し、10巡以内の超高速スコアアタックと全国ランキング（Supabase）をブラウザだけで即座に体験・共有できる点。

## 4. 技術スタックの選定理由と自習計画
- **フロントエンド**：Next.js (App Router) + TypeScript + Tailwind CSS（静的型付けによりエージェント生成コードの破綻を防ぎ、URL共有のみで即時体験可能）
- **バックエンドおよびデータベース**：Supabase (PostgreSQL)（クレジットカード登録不要の無償枠で全国ランキング・デイリーお題・スコア履歴を永続化可能）
- **ホスティング環境**：GitHub + Vercel（`main` ブランチへのプッシュで自動ビルド＆本番配備）
- **自動テスト・自習計画**：Vitest による少牌マイティ牌理・点数計算ロジックの単体テストを導入し、TechTrain Railway の React / TypeScript / DB 課題で知識を補完する。

## 5. 8週間の垂直スライス開発計画
- **第1週**：少牌マイティ（12枚＋★マイティ）の和了・待ち牌判定エンジン＋プレイUI＋Vercel初公開（最小の全層貫通）。
- **第2週**：実牌画像（`pai-images`）の統合と、Supabase を使った「全国ハイスコアランキング（TOP 10）」の永続化。
- **第3週**：リアルタイム待ち牌チェッカーの強化（打牌選択時のプレビュー・残り枚数・最高打点表示）と操作性向上。
- **第4週**：友人・ゼミ生による実機テストとフィードバック収集、少牌マイティへの集中ピボット（UI簡素化・ルール説明の改善）。
- **第5週**：シード固定による「デイリーお題（全員同じ配牌・同じツモ順でスコアを競う機能）」と Supabase 日別ランキングの実装。
- **第6週**：少牌マイティ「CPU対戦（1対1・AI相手との高速スコア/早アガリ対決）」のプロトタイプ実装。
- **第7週**：Supabase Realtime を活用した「合言葉ルームによるオンライン友人対戦（または同期スコアバトル）」の検証実装＋セキュリティ点検（RLS・環境変数分離）。
- **第8週**：実運用データ・全国ランキング・対戦機能を用いた成果実演と総括（今後の4人オンライン対戦拡張に向けた展望）。

## 6. ハーネス設計と品質管理方針
- **自動テストの導入計画**：Vitest を導入し、`src/engine/` 配下のワイルドカード全34種代入探索・多面待ち抽出・役/点数計算に対する単体テストを毎回実行する。
- **エージェント規範定義の導入計画**：`AGENTS.md` に型検査（`npx tsc --noEmit`）・テスト（`npm test`）・UI/ロジック分離・環境変数保護ルールを明文化する。
